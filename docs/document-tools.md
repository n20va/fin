# Чтение финансовых документов и генератор объёма

Обновление от 11 ноября 2026 года: преобразование файлов между форматами удалено. Поддерживается извлечение финансовых данных из фиксированных шаблонов проекта и включение проверенных документов в расчёт.

## Поддерживаемые шаблоны

| Документ | Формат | Что читается |
| --- | --- | --- |
| Договор | DOCX, одностраничный PDF | Номер и дата, контрагент и его ID, сумма, валюта, направление, счёт компании, срок оплаты, ID обязательства и ожидаемая дата |
| Счёт | XLSX | Номер и дата, договор, контрагент, валюта, счёт компании, направление, срок и ожидаемая дата, ID обязательства, позиции и итог |
| Акт | Одностраничный PDF | Номер, дата признания и статья ОПиУ, счёт и договор, контрагент, сумма, валюта и срок оплаты |
| Банковская выписка | CSV, XLSX | Счёт, валюта, период, входящий/исходящий остатки, обороты, ID/даты/суммы операций, направления, обязательства и статьи ДДС |
| План | CSV, XLSX | ID, контрагент, счёт, валюта, направление, сумма, срок, ожидаемая дата и назначение |

Образцы находятся в разделе «Документы» и в поставляемом `output/documents/`. Новая генерация добавляет явные поля «Обязательство ID» и «Ожидаемая дата». CSV использует UTF-8 и шапки проекта; числа имеют точку перед копейками, даты имеют формат `yyyy-MM-dd`. Для XLSX также принимаются ячейки дат Excel без времени, shared strings и сохранённые результаты формул. Формула без сохранённого результата отклоняется. Допускается один шаблон в файле; непустые посторонние листы, произвольные тексты и таблицы не угадываются.

У старых наборов в документах отсутствуют внутренний ID обязательства и ожидаемая дата. Для уже известных документов эти значения сохраняются из индекса и ручных настроек набора с явным предупреждением об источнике. Суммы, сроки, валюты, даты признания и статьи ОПиУ всё равно читаются из файлов. Для нового счёта эти поля нужно заполнить в шаблоне; вымышленные значения не подставляются.

## Загрузка, проверка и применение

1. Откройте «Чтение документов». Выберите файл текущего набора либо загрузите связанный комплект: до 100 файлов общим объёмом 100 МБ.
2. Нажмите «Прочитать финансовые данные». В фоне читаются поля, их расположение и строки реестров. Исходные файлы сохраняются отдельно.
3. Проверьте суммы, даты, реквизиты, предупреждения и список заменяемых представлений. Интерфейс показывает поля и первые 100 строк каждой таблицы.
4. Отметьте проверку и нажмите «Включить в расчёт и пересчитать». До этого текущий набор не изменяется.

Повторный логический документ определяется по прочитанным реквизитам. При подтверждении его прежние представления заменяются перечисленными в просмотре файлами; новый документ добавляется. Содержимое других исходников и большого корпуса не переписывается.

Применение создаёт отдельную подготовку, повторно проверяет SHA-256 оригиналов и текущих источников, сверяет договор/счёт/акт и финансовые строки, пересчитывает календарь и ОПиУ/ДДС. Несовпадение сумм, реквизитов, сроков, контрольных остатков выписки, неизвестное обязательство или один ID с разными финансовыми значениями останавливают применение. Ошибка, отмена или устаревшее подтверждение сохраняют текущий набор. Успех публикует новую подготовку и удаляет прежний рабочий датасет.

В расчёте нет подстановки финансовых сумм из `DemoGenerator.Build`. Генератор сначала пишет документы, затем применяется тот же читатель шаблонов. Начисления берутся из актов, обязательства из счетов с проверкой договора, банковский факт из выписок, планы из реестров. Компания читается из исходников; документы разных компаний в одном наборе отклоняются. Период и демонстрационные валютные курсы остаются настройками расчёта. Прочитанные поля и их происхождение сохраняются вместе с SHA-256; повторный запуск использует извлечение только при совпадении хеша и версии читателя; изменённый исходник читается заново.

## PDF и OCR

Текстовый PDF читается локально через PdfPig. Для сканов можно включить автоматическое или принудительное OCR через Poppler и Tesseract с русской/английской моделями. Документы не отправляются во внешние сервисы. Поддерживаются одностраничные PDF-шаблоны проекта, а не произвольная вёрстка.

OCR может ошибаться в буквах, номерах и валюте. Если поля неоднозначны, показываются распознанный текст и предупреждение; включение в расчёт заблокировано даже при отметке подтверждения. Нужно исправить исходный файл либо загрузить PDF с текстовым слоем и повторить чтение. Валюта, сумма или номер не восстанавливаются догадкой.

Задания идут через `POST /api/jobs/read`, результаты видны через `GET /api/jobs/<id>`, применение требует `POST /api/jobs/<id>/apply` с `confirmed: true`. API старого конвертера `/api/conversions` и скачивания преобразованного файла удалены. Новые выходные DOCX/PDF/XLSX/CSV не создаются.

## Генерация объёма

Начиная с обновления от 12 ноября 2026 года большой корпус генерируется с неровным календарём поступлений и выплат. Для каждой валюты и направления задаётся воспроизводимый случайный профиль тихих и пиковых дней. Дополнительно варьируются суммы, отсрочки, ожидаемые даты, доли частичных оплат и разбиение платежей. Общие пики сохраняются даже после суммирования миллионов строк. Отдельный режим в интерфейсе выбирать не нужно: это поведение новых наборов и новых порций при догенерации. Существующие документы сохраняются. Банковские записи охватывают весь квартал; дата среза определяет, какие из них входят в факт и уменьшают долг.

В разделе «Генератор данных» задаются число и единица МБ/ГБ. Минимум 20 МБ. Единицы десятичные: 1 МБ = 1000000 байт, 1 ГБ = 1000000000 байт. Значение сохраняется в браузере. Отдельные команды CLI для новых функций не добавлялись.

Над формой показан фактический размер открытого датасета и число файлов. При открытии страницы и по кнопке «Обновить размер» сервер суммирует размеры документов, таблиц, JSON, HTML и манифеста этого набора. Оригиналы загрузок и результаты чтения в этот размер не включаются. При просмотре автономного HTML доступен только сохранённый размер из метаданных большого корпуса с соответствующей подписью.

Генерация запускается только в разделе «Генератор данных», кнопкой «Сгенерировать и заменить». Отдельная кнопка на главной и её HTTP-метод удалены. После завершения браузер автоматически открывает новый набор. Ссылка на заменённую страницу переводит к текущему набору; файлы удалённого набора больше не выдаются.

Новый набор сначала полностью создаётся во временной папке. После успешной проверки обновляется `current.json`, затем удаляются предыдущие датасеты. При ошибке или отмене генерации временная папка удаляется, текущие данные сохраняются. При запуске приложение также очищает ранее накопленные наборы, оставляя выбранный текущий. Загруженные оригиналы и результаты чтения в `.jobs/` сохраняются отдельно.

Если старые файлы заняты другой программой или недоступны для удаления, текущий готовый набор остаётся рабочим, а интерфейс показывает предупреждение. После закрытия документов и перезапуска очистка повторяется.

Каждый набор содержит прежний контрольный пример и большой корпус реестров CSV, XLSX, DOCX и PDF. Корпус включает 1000 синтетических контрагентов, договоры, счета, акты, обязательства и банковские оплаты. У документов есть внутренние идентификаторы и человекочитаемые номера. Между реестрами сохраняются ссылки; суммы актов и счетов совпадают; полные и частичные оплаты не превышают обязательства; непогашенная сумма равна сумме обязательства за вычетом оплат. Начисления и банковские оплаты представлены отдельно.

Новые записи имеют уникальные идентификаторы, различные суммы, сроки и назначения. Пустые байты, разреженные файлы и копирование наполнителя для увеличения размера не используются. Генератор пишет порциями до 20000 обязательств, поэтому память не растёт пропорционально объёму корпуса. Браузер получает список файлов по 25 записей.

Цель относится ко всем файлам внутри папки созданного набора, включая документы, JSON, CSV, HTML и манифест. Проверяется фактический размер файлов: от цели до цели + 100000000 байт. Пока новый набор создаётся, прежний остаётся доступным. Поэтому перед запуском требуется свободное место на весь новый объём и резерв 5 ГБ; после успешной замены старые данные удаляются.

Все основные документы, подтверждённые импорты и весь корпус участвуют в календаре, ДДС и ОПиУ. Сервер читает части по 20000 обязательств и проверяет связи договора, счёта, акта, обязательства и банковской оплаты. Один комплект создаёт одно обязательство. Суммы и категории манифеста не используются как финансовые входы. Оплаты берутся из банковского реестра, начисления из актов, прогноз из остатка обязательств на выбранную дату. Отрицательный фактический остаток большого учебного корпуса не скрывается.

В новом наборе одинаковое число исходных файлов каждого из четырёх форматов, включая контрольные документы и справочник контрагентов. При догенерации поровну распределяются только новые файлы; прежний CSV-корпус не переписывается. Уменьшение удаляет связанные части целиком, поэтому пропорция оставшихся файлов может измениться. Все форматы содержат настоящие ячейки или видимый текст. PDF-реестр корпуса многостраничный, использует фиксированный текстовый шаблон ASCII и стандартный Courier; его читатель извлекает отображаемые операторы текста. Это отдельный шаблон от одностраничных договоров и актов с OCR. Произвольные многостраничные PDF-таблицы не принимаются.

`corpus-accounting.json` содержит производный индекс частей, SHA-256 прочитанных исходников и компактные финансовые события. Кэш проверяется по версии читателя, составу, размерам, времени изменения файлов и конфигурации компании/счетов. Изменение источника приводит к повторному чтению; конфликт блокирует публикацию. Файл можно восстановить из исходников. На первом запуске со старым большим набором сервер читает его полностью до открытия страницы; следующие запуски используют актуальный кэш. Размер кэша входит в размер датасета.

Браузер пересчитывает агрегаты точно в целых копейках на выбранную дату. Реестры обязательств, начислений и банковских операций выдаются по 50 строк: `GET/POST /api/datasets/<id>/records`. Поиск ограничен четырьмя частями за запрос и продолжается кнопкой «Далее». Точный ID вида `BO-...` сразу открывает нужную часть. Карточка `GET /api/datasets/<id>/obligations/<id>` показывает внутренние ID, номера документов, оплаты и реальные пути источников. Ручная регистрация оплаты остаётся демонстрацией для основных документов; записи корпуса доступны для просмотра и проверки.

Пути внутри рабочей папки: по умолчанию `output/runtime/`; для локальной проверки используется `.test-artifacts/web/` через `--output`. Поставляемый эталонный пример `output/` служит проверкам и автономному просмотру и не является архивом рабочих наборов.

| Путь | Содержимое |
| --- | --- |
| `generations/<id>/documents/` | Контрольные 100 документов DOCX/PDF/XLSX/CSV |
| `generations/<id>/bulk/counterparties.csv` | Контрагенты большого корпуса |
| `generations/<id>/bulk/part-*-contracts.csv/xlsx/docx/pdf` | Договоры с номерами, валютой и условиями |
| `generations/<id>/bulk/part-*-invoices.csv/xlsx/docx/pdf` | Счета со ссылками на договоры |
| `generations/<id>/bulk/part-*-acts.csv/xlsx/docx/pdf` | Акты и сведения о признании доходов/расходов |
| `generations/<id>/bulk/part-*-obligations.csv/xlsx/docx/pdf` | Обязательства, оплаченные суммы и остатки |
| `generations/<id>/bulk/part-*-bank.csv/xlsx/docx/pdf` | Банковские оплаты со ссылками на обязательства |
| `generations/<id>/volume-manifest.json` | Состав корпуса, строки, размеры, SHA-256 и контрольные суммы по валютам |
| `generations/<id>/corpus-accounting.json` | Восстанавливаемый индекс источников и финансовые агрегаты всего корпуса |
| `.jobs/<id>/input-*.docx/pdf/xlsx/csv` | Сохранённые оригиналы загруженных или выбранных файлов; через публичную выдачу наборов не доступны |
| `.jobs/<id>/job.json` | Состояние задания и предупреждения |

Задания выполняются одним фоновым обработчиком с очередью до восьми ожидающих заданий. Во время генерации календарь доступен; следующие задания чтения ожидают очередь. Можно отменить задание. При штатной отмене или ошибке генерации незавершённый набор удаляется, указатель текущего успешного набора сохраняется. При успехе остаётся только новый датасет. После перезапуска незавершённое задание отображается как прерванное; исходный файл чтения остаётся на диске. Успешные задания доступны после перезапуска.

## Корректировка текущего размера

В форме «Генератор данных» появился список «Действие»:

- «Создать новый набор»: значение задаёт итоговый размер другого набора, минимум 20 МБ.
- «Догенерировать данные»: значение задаёт добавляемый объём, минимум 1 МБ. Существующие документы, записи и seed сохраняются; календарь и отчёты пересчитываются с учётом добавленных записей. Создаются новые связанные реестры с уникальными идентификаторами. При добавлении после удаления номера ранее удалённых записей не используются повторно. Фактический прирост составляет от запроса до запроса + 100 МБ.
- «Удалить часть данных»: значение задаёт удаляемый объём, минимум 1 МБ. Удаляются последние части корпуса целиком: договоры, счета, акты, обязательства и относящиеся к ним оплаты. Выбирается ближайший объём с отклонением до 100 МБ в любую сторону. Контрольные документы и справочник контрагентов сохраняются; календарь и отчёты пересчитываются по оставшимся записям. Доступный для удаления объём показан возле текущего размера; превышение отклоняется.

После успеха карточка размера показывает фактическое изменение, запрос и размеры до/после. Число обязательств, суммы счетов и оплат по валютам, размеры и SHA-256 оставшихся файлов согласованы с обновлённым манифестом. Используются прежние очередь, прогресс и отмена. Запросы корректировки идут через `POST /api/jobs/resize` с `datasetId`, `operation` (`add`/`remove`) и `bytes`; если набор уже заменён, запрос отклоняется.

Корректировка готовится отдельно и публикуется через существующий `current.json`. Неизменяемые файлы корпуса временно используются через жёсткие ссылки в той же файловой системе; JSON/HTML и контрольные файлы копируются отдельно. Содержимое общих файлов не перезаписывается. При ошибке или отмене удаляется только временная подготовка; после успеха остаётся один рабочий набор. Системные вызовы: [Windows CreateHardLinkW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createhardlinkw), [macOS link](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/link.2.html).

Для добавления проверяется свободное место на добавляемый объём и резерв 5 ГБ; для удаления оставляется 20 МБ на подготовку метаданных и контрольных файлов. Если жёсткие ссылки недоступны, используется обычное копирование с дополнительной проверкой места; для него может потребоваться место под текущие данные. Полные копии прошлых наборов после успеха не сохраняются.

## Установка на macOS

Нужен .NET SDK 10. Чтение DOCX/XLSX/CSV и текстового PDF не требует внешнего офисного приложения. Для OCR нужны Poppler, Tesseract и языковые модели:

```sh
brew install tesseract poppler
mkdir -p .local-tools/tessdata
curl -fL https://raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/rus.traineddata -o .local-tools/tessdata/rus.traineddata
curl -fL https://raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/eng.traineddata -o .local-tools/tessdata/eng.traineddata
dotnet run --project src/FinPlan
```

## Установка на Windows

Установите .NET SDK 10. Для OCR, например через Chocolatey:

```powershell
choco install tesseract poppler -y
New-Item -ItemType Directory -Force .local-tools/tessdata
Invoke-WebRequest https://raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/rus.traineddata -OutFile .local-tools/tessdata/rus.traineddata
Invoke-WebRequest https://raw.githubusercontent.com/tesseract-ocr/tessdata_fast/main/eng.traineddata -OutFile .local-tools/tessdata/eng.traineddata
dotnet run --project src/FinPlan
```

При нестандартной установке задайте `FINPLAN_TESSERACT`, `FINPLAN_PDFTOPPM` и `FINPLAN_TESSDATA`. Состояние OCR и языков показано на странице чтения. PdfPig 0.1.16 зафиксирован в NuGet lock-файлах. Документация и лицензии: [PdfPig](https://github.com/UglyToad/PdfPig), [Tesseract](https://tesseract-ocr.github.io/tessdoc/), [Poppler](https://poppler.freedesktop.org/).
