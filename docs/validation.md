## Вариативность генерации от 12 ноября 2026 года

Исправлена причина сглаживания большого корпуса: даты больше не вычисляются циклически по ID, отсрочка не фиксирована на 7 днях, оплаченные доли не повторяют четыре значения. Пики задаются общими профилями по валюте и направлению, поэтому не исчезают после агрегирования большого числа записей. Расчётный модуль и график не изменялись.

Три тестовых набора с seed 0, 42 и 2147483647 содержали 63438–73195 обязательств. Пять крупнейших дней давали 35,76–74,98% соответствующего будущего потока по валюте и направлению; знак дневного суммарного потока менялся 30–46 раз. Проверены более 100 разных долей частичной оплаты, разные отсрочки и задержки, банковские даты по всему кварталу, воспроизводимость содержимого при одинаковом seed. Проверки связей и денежных сумм выполнялись по реальным файлам всех четырёх форматов. Результаты: `.test-artifacts/variation-0.json`, `.test-artifacts/variation-42.json`, `.test-artifacts/variation-2147483647.json`.

Локально прошли 41 C#-проверка без пропусков, включая OCR и сверку полного реестра с агрегатами на пяти датах, и 25 JavaScript-проверок. Изменения относятся к генератору большого корпуса, его тестам и документации. Сохранённый пользовательский набор на 50 ГБ сам по себе не меняется; для нового распределения требуется генерация или догенерация.

## Границы

Поддерживаются согласованные шаблоны проекта. Универсальная обработка всех текстов и таблиц не реализуется. PDF-шаблоны одностраничные; сканы могут требовать исправления оригинала. Ожидаемые даты и внутренние ID старых шаблонов, которых в файлах не было, отмечаются как сохранённые ручные настройки и привязки. Денежные суммы и даты признания из модели генератора не подставляются.

Начисления формируются по актам; план и факт оплаты не смешиваются. Большой корпус участвует в расчётах через агрегаты, восстановленные из файлов. Реестр и основания отчётов выдаются сервером по страницам. Существующий набор на 50 ГБ сохранён в прежних CSV; смешанная генерация проверена отдельно на 1 ГБ, полная новая генерация смешанного набора на 50 ГБ не выполнялась. Ручные оплаты браузерной демонстрации не стали постоянными записями в БД.

## Причины изменений

| Изменение | Основание |
| --- | --- |
| Удалены запись выходных форматов, API/страница конвертера и зависимость от LibreOffice | Пользователь отказался от конвертации |
| Сохранены низкоуровневые читатели OOXML/CSV/PDF и OCR | Нужны для чтения финансовых шаблонов из содержимого файлов |
| Добавлены читатель полей и единый финансовый импорт | Раньше договоры, счета и акты брали финансовые данные из модели генератора |
| Расчёт и проверка повторов используют прочитанные реквизиты | Требуются настоящие данные источников, сверка связей и отсутствие двойного учёта |
| Новые шаблоны содержат ID обязательства и ожидаемую дату | Эти поля отсутствовали в старых исходниках; их нельзя выдавать за извлечённые |
| Просмотр, подтверждение и атомарное применение | По выбору пользователя загруженные документы включаются в расчёт после проверки |
| Проверка хешей, откат, сохранение оригиналов и корпуса | Устаревшее подтверждение, ошибка или отмена не должны менять текущие данные |
| Повторная очистка частично удалённого набора | На Windows занятый файл может остаться после удаления dataset.json; отдельный маркер сохраняет принадлежность папки для повторной очистки |
| Генератор и регулирование объёма сохранены | Изменился запрос к работе с документами, а не к объёму данных |
| Расчёт всего корпуса и компактные события | Требование учитывать все исходные записи без загрузки 50 ГБ в память браузера |
| Равное количество CSV/XLSX/DOCX/PDF | Уточнение пользователя: равенство по количеству файлов |
| Постраничные реестры и реальные источники | Возможность проверить каждое обязательство и основания отчётов |
| Режим GC для локального приложения | Ограничить удержание памяти при проходе по большому корпусу |
